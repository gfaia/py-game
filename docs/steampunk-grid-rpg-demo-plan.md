# 蒸汽朋克网格 RPG 最小演示计划

## 目标

在不修改现有游戏的前提下，新增一个可直接运行的 Pygame 演示。演示用一张小型网格地图展示蒸汽朋克风格的场景和完整的基础流程。

玩家从废弃的黄铜车站出发。机械师 NPC 要求玩家清除一台失控的发条哨兵。玩家击败敌人后返回 NPC，完成任务。

## 范围

首个版本只包含下列内容：

- 一张 15 × 11 的手工定义地图。
- 墙壁、地板、黄铜管道和锅炉等地形显示。
- 玩家按方向键进行四方向网格移动。
- 墙壁和其他实体阻止移动。
- 一个机械师 NPC 和一个失控发条哨兵。
- 玩家与相邻敌人的回合制攻击。
- 玩家与相邻 NPC 的交互和任务状态变化。
- 显示生命、任务文本和操作提示的 HUD。
- 重新开始和退出控制。

首个版本不包含地图编辑器、多个关卡、随机生成、背包、装备、存档、音频或复杂敌人 AI。

## 用户流程

1. 用户运行 `python3 steampunk_rpg/main.py`。
2. 游戏显示黄铜车站和初始任务提示。
3. 用户移动到机械师相邻格，并按 `E` 接受任务。
4. 用户移动到发条哨兵相邻格，并按 `Space` 攻击。
5. 每次攻击后，存活的哨兵立即反击一次。
6. 用户击败哨兵后回到机械师相邻格，并按 `E` 完成任务。
7. HUD 显示任务完成信息。
8. 用户按 `R` 开始新游戏，或按 `Esc` 退出。

## 架构

采用现有项目使用的 Pygame 帧循环：处理事件、更新游戏状态、绘制画面。每个输入动作只改变一次游戏状态，所以网格移动和战斗结果保持稳定。

`Game` 负责窗口、资源、帧循环、输入路由和场景重置。`World` 负责地图、实体位置、移动验证、交互和战斗规则。`Entity` 是玩家、NPC 和敌人的共享基础对象。`Renderer` 将世界状态绘制为颜色方块、简单图形和文本。

地图使用字符行定义。每个字符表示一个格子类型。`#` 表示墙壁，`.` 表示地板，`=` 表示黄铜管道，`B` 表示锅炉。实体位置由独立的坐标数据定义，避免把动态状态写入地图。

## 目录和文件

新增 `steampunk_rpg/` 目录，不修改 `snake/`、`jumper/`、`air_shooter/`、`tilemap/` 或 `demon/`。

`steampunk_rpg/settings.py` 定义窗口大小、格子大小、颜色、字体和操作键。

`steampunk_rpg/map_data.py` 定义地图字符行、出生点和固定实体位置。

`steampunk_rpg/entities.py` 定义玩家、机械师和发条哨兵的数据与共享行为。

`steampunk_rpg/world.py` 定义坐标检查、移动、交互、战斗、任务状态和重置规则。

`steampunk_rpg/main.py` 定义 `Game`，并负责 Pygame 初始化、事件处理、更新和绘制。

`README.md` 增加最小演示的启动命令和操作说明。

## 核心规则

所有坐标使用整数网格坐标 `(column, row)`。渲染时再转换为像素坐标。

玩家只能移动到地图范围内、可通行且没有实体占用的相邻格。按方向键时，系统先验证目标格，再更新玩家位置。

玩家按 `E` 时，系统优先查找相邻 NPC。首次交互将任务状态从“未接受”改为“进行中”。敌人死亡后交互将状态改为“完成”。

玩家按 `Space` 时，系统查找相邻敌人。若找到敌人，玩家造成固定伤害。敌人存活时造成固定反击伤害。敌人生命为零时从世界移除。

玩家生命为零时，游戏显示失败状态。用户按 `R` 后，系统恢复初始地图、实体、生命和任务状态。

## 实施步骤

1. 创建 `steampunk_rpg/` 和基础配置。定义常量、颜色和输入键，使窗口与网格尺寸一致。
2. 创建地图数据。设计一张包含起点、障碍、管道、锅炉、NPC 和敌人的小型车站地图。
3. 创建实体模型。实现位置、名称、生命、攻击力和存活状态，并为每种实体设置蒸汽朋克显示颜色。
4. 创建世界规则。实现格子可通行检查、实体占用检查、单格移动、相邻交互、相邻战斗和任务状态转换。
5. 创建游戏入口。实现帧循环、键盘事件、世界重置和退出逻辑。
6. 创建渲染代码。绘制地形、实体、网格、生命条、任务文本、状态提示和结束信息。
7. 更新根目录 `README.md`。说明依赖、启动命令和全部按键。
8. 手动验证完整流程。验证不能穿墙，验证交互顺序，验证战斗反击，验证任务完成，验证失败后重置。

## 验收标准

从仓库根目录运行 `python3 steampunk_rpg/main.py` 时，程序打开一个可关闭的窗口。

玩家不能离开地图，也不能穿过墙壁、NPC 或存活的敌人。

玩家只能从相邻格接受或完成任务，也只能从相邻格攻击敌人。

发条哨兵在受到攻击且存活时反击。它死亡后不再阻挡移动或反击。

HUD 始终显示玩家生命、当前任务状态和操作提示。任务完成后，HUD 显示完成消息。

按 `R` 后，游戏回到初始状态。按 `Esc` 或关闭窗口后，程序正常退出。

## 风险与处理

Pygame 事件会在单帧内重复读取。首个版本只在 `KEYDOWN` 事件中处理移动、交互和攻击，避免一次按键产生多次动作。

字体在不同系统中可能不同。首个版本使用 Pygame 默认字体，避免依赖本机字体文件。

图像素材会增加路径和授权问题。首个版本使用程序绘制的色块和几何图形，后续再替换为授权的蒸汽朋克素材。
